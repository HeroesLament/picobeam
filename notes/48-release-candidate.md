# 48 — v0.1.0-rc.1

Forty-seven notes of "what we learned today". This one is "what there
is", which is a different document and has not existed until now.

## What it is

An Erlang machine that runs Elixir on an FPGA. Not a simulation of one:
`priv/demo/board_demo.ex` goes through the real Elixir compiler, down
through Core Erlang, out as bundles, into a 42,203-LUT4 design on a
ULX3S, and the answer comes back off the debug UART (`notes/44`).

```
gate        66 testbenches, 0 failed
model       75 tests, 0 failed
opcodes     61 of 63 executed by a real program
OTP shapes  14 of 15 (notes/30)
silicon     42,203 LUT4 (50%), 116 DP16KD (56%), 26 MULT18X18D
            Fmax 14.59 MHz, closing at 12.00 MHz, two engines
```

The two opcodes are `recv`, which `Encoding` deliberately refuses
because the fused form does not exist in hardware, and `recv_hash`,
which is wired and has no emitter. Neither is debt.

## What got cleaned up to get here

**The M2 decision, finally made.** `notes/23` counted 2,478 lines of
superseded RTL and said *"keeping them is defensible; leaving the
decision unmade is not."* `notes/27` counted the same 2,478 lines and
said the same sentence. They are in `attic/` now — out of the compile
path, with a README saying what each was superseded by and why it is
kept rather than deleted. M2 is the sequential engine every M3 number
was measured against, and a benchmark whose baseline has been deleted is
a number without a denominator.

Nothing under `lib/`, `scripts/` or `test/` referenced any of it. Moving
them changed no netlist and no test, and `mix test --cover` stopped
averaging in eight modules nothing runs.

**The four ALU micro-ops, closed.** `bor`, `bxor` and `cmple` had been
unit-tested against the model since M2 and had never been through the
engine; `yield` and `unlink` were wired and exercised nowhere.
`notes/23`, `notes/27` and `notes/45` each listed them as the cheapest
thing on the board and each carried them forward. `scripts/mk_bitwise.exs`
is that hour: **56 of 63 to 61 of 63**, first run, no bugs found.

**The README, which was two milestones stale.** It ended at "next is the
heap and the M4 serialiser", listed notes to 21, and described
`lib/pico_beam/rtl/` as "M2". It now says what runs, with the numbers,
and how to run it.

It also carries a correction rather than a quiet edit. The bounds table
used to claim **"GC mutator stall: 0 cycles"**. That is false and has
been false since the collector was wired in: the collector does own the
heap BRAM's second port, but the ROOTS live in the register file and the
frame RAM, and reading them stops the process that owns them. 8% of wall
clock in `notes/41`; a 3.8x cut to the longest pause and no cut to the
total in `notes/46`. Zero is the target and is not the number.

**`AGENTS.md`, which opened with "Nothing is built yet."** It now opens
with what is built, points at `notes/26` as required reading, and records
the two recurring failure shapes — a fact decided in one place and copied
into another, and a signal named for what is happening used for what is
safe — because those are worth more to the next person than any
individual fix.

## What is knowingly not in it

* **Cross-engine spawn.** Designed in `notes/47`, four state machines,
  unbuilt. Two engines pass messages; they cannot hand each other work.
* **`register`/`whereis`, ETS, distribution, external IO** beyond the
  debug UART.
* **`call_ext` and an export table.** One module plus a prelude. No code
  loading; `notes/42` designs BEAM's two-version rule and nothing
  implements it.
* **Sixteen registers per window.** Not a missing feature — a limit, and
  the one that bites while writing ordinary Elixir. `notes/26` entry 22.
* **A concurrent collector in the full sense.** `notes/46` is
  incremental: the pause is one process's live set rather than the
  engine's, and it is not zero.

`notes/45` is the honest summary of the shape of this: deeper than ECOMP
on what an Erlang machine *is* — the runtime is gates, not machine code —
and nowhere near on what one has to *hold*. ECOMP ran 16,000 lines of
call control in 2000. The largest program picoBEAM has ever run is 414
bundles.

## How to check it

```sh
git clone https://github.com/HeroesLament/ehdl ../ehdl
mix deps.get && mix compile
mix test                        # 75
bash scripts/run_tbs.sh quick   # 66
```

and on a board with yosys, nextpnr-ecp5 and fujprog:

```sh
bash scripts/build_m5.sh
fujprog -b 115200 -t _emit/ulx3s/picobeam_m5.bit
fujprog -P /dev/cu.usbserial-XXXX -b 115200 -a _emit/sd/board.img -t
```

The last line should print `OO=9e` and `NN=00` — the checksum, and no
process that died of anything but `normal`.

## The one thing worth saying about the number 66

The gate is the release. Every image it loads was generated by running
the program on `PicoBEAM.Machine` and dumping what it printed; the
netlist is compared against that word for word. There is no expectation
in this repo that a human wrote down. That is why the count is worth
quoting and why "66 testbenches" is a stronger sentence than it looks.

## Amendment (Phases 1–5 of `notes/53`)

The gap list above aged quickly, in the right direction:

* **Registered names** shipped (`notes/50`) and then became NODE state
  (`notes/53`): one shared CAM, `whereis/1` answers the same everywhere.
* **Sixteen registers** stopped biting: the recycling front end
  (`notes/50`) frees a register at its last read, and ordinary Elixir
  fits. The limit is now sixteen LIVE values.
* **Cross-engine spawn** shipped (`notes/49`), and supervision followed
  it across the ring (`notes/54`): links, monitors, `exit/2` and both
  noproc replies are ring packets. A supervisor on one engine restarts
  a registered server on the other; `tb_super2` is that sentence as a
  gate, and the board line `OO=05 XX=01` is it on silicon.
* The counts in "How to check it" are now **89** (`mix test`) and the
  gate grew `tb_names2`, `tb_slink2`, `tb_mon2` and `tb_super2` — all
  two-engine, all model-compared, same rule as before: no expectation
  a human wrote down.

Still open, still honest: `call_ext`/code loading (`notes/42`), ETS
(now obviously a shared node unit), the collector's pause reaching
zero, and distribution — which `notes/53` promoted to mean a second
board.
